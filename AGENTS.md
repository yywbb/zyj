# Project instructions

## Workspace quirks

- `._*` files are macOS AppleDouble metadata, not source; exclude them from searches and staging. Existing sidecars under `.git/refs` and `.git/objects/pack` make `git fsck` report invalid refs/packs; do not treat `._*` entries as real Git refs or objects.

## Run and verify

- Python uses only the standard library. Run regressions with `python3 -B -m unittest -v test_mock_server test_build_local_apk test_admin`; one case: `python3 -B -m unittest -v test_mock_server.ReplayRoutingTests.test_select_does_not_receive_city_init_at_same_sequence`. Tests use temporary saves/configs and loopback ephemeral ports, never the real **14600/14601** ports. Syntax check: `python3 -m compileall -q -x "[.]_" mock_server.py zyj_server build_local_apk.py test_mock_server.py test_build_local_apk.py test_admin.py` (skip AppleDouble metadata); frontend: `node --check zyj_server/admin/static/app.js`. No CI, linter, or formatter is configured.
- Both entrypoints use argparse: `--help` is safe, unknown flags are rejected. There is no build dry-run.
- `python3 mock_server.py` starts **`0.0.0.0:14600`** without invoking ADB. Phones and emulators connect directly to the computer's LAN IPv4 address. Keep this passwordless server on a trusted network; account selection is not authentication. Do not expose it to the Internet.
- Login opcode **1000** uses `ParamS` from `params_pb.lua`, not `sessionvalidate_pb.lua`: the first `Param.s` is `local_account_<1..1000>`. Bind the connection before loading state; never identify an account by client IP or mutate global `SAVE_PATH` per connection. One active connection per account; release it on every exit, including failed loads. Abrupt network loss may wait for TCP disconnect before releasing the old session.
- Account 1 retains `role_save.json`; other accounts use `accounts/<id>/role_save.json` beside the script. Pass the bound account's save path to `Session`; all writes use `player.save_role()` / `prepare_recorded_responses()`. `--account N --reset` / `--reset-guide` affect only N (default 1), then start the shared server. Bind the port before resetting to avoid deleting a live server's save. Back up progress first; `role_save.json` filenames are Git-ignored at every depth. Worktrees do not automatically share/copy runtime saves.
- Device verification requires a separately supplied/rebuilt APK. Install by file transfer or optional `adb install -r zyj_local.apk`, then launch from the app icon. Verify phones/emulators can play with ADB disconnected. Check both fresh-account progression and reconnect/resume when changing guide or replay behavior; syntax checks cannot validate gameplay.

## Server modules

- `mock_server.py` owns CLI/LAN TCP, account binding and root-relative resource paths. It loads configuration/recordings at startup, not import time, and passes the account-specific path and configuration explicitly into `zyj_server.session.Session` only after login.
- `Session.handle(opcode, seq, body)` returns ordered, fully packed frames without a socket. Any exception ends the connection; do not reuse a failed session. Recordings are shared, but each session owns a `Replay` with independent counters.
- `accounts.AccountStore` owns account paths, login occupancy and the shared offline-maintenance lock. Pass one store to TCP `handle_client(conn, addr, store)` and the admin server. Reserve before loading, release on load failure/disconnect, and never release another connection's reservation after duplicate login rejection. Dashboard snapshots read atomic files, not mutable session state; reads must not settle stamina or persist migrations.
- The admin HTTP server starts with the game process at **127.0.0.1:14601** (`--admin-port`, 0 = ephemeral) and shuts down with it. Keep HTTP routing in `admin/http.py`, save projections in `admin/views.py`, and frontend files in `admin/static/`; no framework/build dependency. Enforce local Host/Origin and per-process write tokens. Maintenance is offline-only with revision checks; backups under `backups/accounts/<id>/` must succeed before reset/restore. Restore validates through `Session` and saves through `player.save_role()`. CLI resets use the same backed-up path.
- `configuration.py` is the shared server/APK source: `configs_sec5.zip` plus optional sibling `config_overrides.json`. Only four recovery props, first-day tasks80001/80030, and liveness16 have editable fields. Validate types, ranges and reward IDs; back up prior overrides under `backups/configs/` and reject stale revisions. Changes require server restart and an APK rebuild, not live session mutation. Inject the same overrides into both APK sections, preserving `patch_guide_step()` and avoiding duplicate ZIP entries; do not remove original-only configs. Runtime saves, overrides and backups are Git-ignored.
- `zyj_server/` separates protocol, guide, activities, player persistence/state, replay matching, and session dispatch. Do not import the entrypoint back into these modules or re-export their helpers from it; tests import the owning module and use temporary save paths. Activities generate protocol/state changes without importing player; player applies their rewards and saves the entire response group.

- Build with `python3 build_local_apk.py --server-ip <computer-LAN-IPv4> --accounts 2` (`--accounts` defaults to 2, range 1..1000). Supply the original **`z7_7_4.apk` beside the script**; APKs are ignored and not distributed in Git. Offline configs come from tracked `configs_sec5.zip`; signing uses `debug.keystore`. Never substitute an invented LAN address in a delivered APK.
- `find_tool()` discovers native **`zipalign` / `apksigner`** and Windows **`.exe` / `.bat`** names on `PATH`, then under `ANDROID_HOME/build-tools`; `.bat` runs through `cmd /c`.
- `assets/GameServer.json` supplies all local account slots with the same LAN IP and port. - **Editing `scripts_clean/` does not change the built APK**. `get_patched_lua_scripts()` decrypts selected scripts directly from the original APK and applies asserted replacements. Implement packaged Lua changes there; the on-disk Lua trees are analysis references.
- `scripts_decrypted/` can contain trailing padding/length bytes. Use `read_script()` to recover actual Lua and `xxtea_encrypt()` to repackage it; encryption must include the final little-endian original-length word.
- Keep `_disabled_patches()` disabled: its client role-reporting/gameplay changes are historical, not part of the active build. Prefer faithful server responses/config corrections over bypassing gameplay.
- Recharge rows are patched by `patch_recharge_script()` into a plain `CCScrollView`, preserving row rendering and rebuilding on status updates. The captured crash is a native `LuaEventHandler::tableCellAtIndex` SIGSEGV; the exact trigger remains unknown. Keep replacement assertions and verify scrolling/taps on device. Research payments bypass SDK checks: patched `UIRechargePre` directly confirms the local **115 → 116** order, never calls real payment. `window_recruit` restores Fengshen token-first/gold fallback, including the next single draw's payment type after the last token is used.
- The build edits the original ZIP/binary resources directly, then **zipalign → apksigner sign → apksigner verify**. Preserve version-specific replacement assertions rather than bypassing them or substituting an Apktool rebuild.
- Config JSONs are injected into **both `assets/config/1/` and `assets/config/5/`**. Tutorial popup hitbox fixes live in `patch_guide_step()`; `GUIDE_CONFIRM_XY` is device-calibrated, not a universal coordinate.

## Wire protocol and guide invariants

- `recorded_frames.json` contains ordered `{c2s, opcode, seq, hex}` records; `hex` is the **payload only**. TCP framing is a 16-byte big-endian `>IIII` header: magic `0x0000EE1C`, payload length, opcode, sequence. Preserve stream buffering/reassembly; one TCP packet is not necessarily one protocol frame.
- The TCP entrypoint handles login **1000** by validating the local account ID, never by replaying a recorded login. Routing then handles live save/guide operations. Ordinary sequence hits **and fallback** must match opcode and complete payload, with counters keyed by `(opcode, payload)`. Opcode **999900** uses embedded IDs **plus the complete request payload**, never sequence alone. Exact payloads distinguish battle maps/points and equipment/general IDs; unimplemented/unmatched ordinary or combination requests return native **999999 + 1999** errors without unrelated pushes or state changes. A response group missing its own acknowledgement is rejected before applying pushes; never synthesize an empty success. Matched, intentionally empty query/acknowledgement bodies remain valid.
- Comb routing normalizes Protobuf field order in the envelope and embedded **201/1003** (`GuideExcute`/`GeneralChangePos`) only, at both indexing and matching. Preserve message order, repeated-value order, unknown fields, duplicate fields and complete values; other embedded data stays opaque. Equivalent encodings share counters. Do not replace this with an ID-only or decoded-dictionary match: the phone's first battle differs from the capture only in envelope `id/data` and guide `section/step` order; slot placement also has independent scalar fields.
- `replay.split_recordings()` splits the unlabelled library whenever a client request sequence decreases or repeats. Match replies by sequence + opcode **within that recording**, including across later requests (`2000` seq 91 / `201` seq 92), never across recordings. Exact `(seq, opcode, payload)` keys retain separate candidate groups; ambiguous keys fall back to per-parameter counters, not merged replies. Sequence-continuous independent captures need explicit labels before import. Tutorial fixtures use the first 410-frame recording, but routing tests load the full mixed library.
- Initialization requires an exact recorded Comb payload too. `master_comb_packets` comes from a recorded **level-1** Role, not the first capture in file order. Matched 26/30-module initializations retain module order, replace common module bodies with this baseline before player save rewrites, and only supplement empty extensions **8101/8105/8109/8110**. Reject missing new-account baselines and nonempty unimplemented extensions; never use a completed account's snapshots as new-account defaults. Only nonempty **205/1024/1027** state pushes are currently restored, in recorded order with **seq 0**, and only for operations with a matching reply.
- Python hand-encodes Protobuf. Use `scripts_clean/*_pb.lua` descriptors as field-number references, especially `guidequery_pb.lua`; client guide behavior is in `guideControl.lua` and `UIGuide.lua`.
- Saves use `guide.sections["<section>"] = {status, step, steps}`; keep `migrate_guide()` compatibility. **1 = in progress, 2 = complete; 0 does not mean in progress.** Resume starts from the reported step + 1; an empty sections response means a fresh account.
